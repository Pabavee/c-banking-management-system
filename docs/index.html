Banking Management System in C++

A complete, menu-driven console application demonstrating inheritance, polymorphism, encapsulation, RAII / smart-pointer memory management and durable file persistence with std::fstream. Every non-obvious choice is explained in an inline comment.

Architecture

BankAccount (abstract)

Owns the shared state (number, owner, balance, history) privately. Public deposit() / withdraw() are template methods that call pure virtual rule hooks.

SavingsAccount

2.5% APR interest applied monthly, a $100 minimum balance, and a $100 minimum opening deposit.

CheckingAccount

$500 overdraft limit. Negative balances are allowed up to the limit and incur a 1.5% monthly overdraft fee.

Bank owns every account through std::vector<std::unique_ptr<BankAccount>> — no new/delete, no leaks, and polymorphic destruction works because the base destructor is virtual. Lookups return non-owning raw pointers, which is the idiomatic way to express "observe, don't own".

  • Requires a C++17-capable compiler (GCC 7+, Clang 5+, MSVC 2017+).
  • Data is saved to bank_data.txt in the working directory after every successful transaction, and again on exit. Delete the file to reset.
  • The file is human-readable, pipe-delimited text (A|… account records followed by T|… transaction records).
  • Try it: create two accounts, transfer funds, quit with option 0, restart — everything is still there.

Ideas to extend it

  • Store money as integer cents (int64_t) instead of double to eliminate all rounding risk.
  • Add PIN authentication with a salted hash, and a Customer class that owns several accounts.
  • Add a BusinessAccount subclass — only one new class is needed thanks to polymorphism and the record factory.
  • Write unit tests (Catch2 / GoogleTest) against BankAccount directly; it has no I/O dependency.
